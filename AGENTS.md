# Notes for coding agents

This repository contains public development code and the last built package
snapshot. Repository updates may precede a release; consult [CHANGELOG.md](CHANGELOG.md).
The complete contributor workflow is in [CONTRIBUTING.md](CONTRIBUTING.md).

- TypeScript/MTS in `src/` is maintained source; `lib/` contains generated
  JavaScript/MJS. Auth and skin packages use the same `src/` and `lib/` layout.
  Change the TypeScript, then regenerate its mapped outputs.
- The browser client needs both build steps: `npm run build:modules` regenerates
  the modules, and `npm run build` bundles the client into `lib/client.js`, the
  `./client` export. Commit the source and both affected outputs together.
- `package.json`, `provenance.json` and `tools/build-map.json` are generated by
  the release projection. Do not hand-edit them. Provenance describes its named
  build snapshot; subsequent repository commits do not rewrite old releases.
- Start with `npm run check -- --plan`. The default checks current Git changes;
  use `file`, `module` or an explicit `task` for a focused scope. Do not run the
  entire test, build or release workflow after each file edit.
- Reuse successful checks when their inputs are unchanged. Choose local checks
  or hosted CI for a batch, rather than duplicating the same checks in both.
- Preserve module cohesion, clear ownership and meaningful failure/recovery
  comments. Long files or lines trigger review, not automatic splitting. Check
  existing implementations before adding another helper with the same purpose.
- The package installs into a DSH profile. Never add install-time scripts,
  network calls or writes outside the install paths.
- Preserve deliberately worded player-facing Chinese during unrelated changes.
- Tests must exercise behavior and be capable of failing. Append-only forks and
  worldline history must not be rewritten or renumbered to make a test pass.
- Development code sync does not authorize tags, GitHub Releases, npm publication
  or production deployment.
